### Added

- **CMS Visual Editing preview server + SPA overlay runtime** (`apps/fe/scripts/preview/{render,stega,inject,auth,handler}.ts`, `apps/fe/scripts/preview-server.ts`, `apps/fe/src/app/preview/visual-editing.ts`, `apps/fe/src/global.d.ts`, `apps/fe/src/app/{index,cache}.ts`, `apps/fe/src/app/controller/index.ts`, `apps/fe/package.json`). A host-agnostic preview core renders the whole site in memory with `perspective: "drafts"` and stega encoding (`getPreviewSite()` — module-scope memo, 30s TTL, in-flight guard), injects prod-equivalent asset tags + an inline drafts `__TMHGNE__` payload + a `window.__PREVIEW__` flag into served HTML, and gates all draft content behind an `@sanity/preview-url-secret` validated `/__preview/enable` flow with a stateless HMAC session cookie (every response `noindex` + `no-store`). `POST /__preview/refresh` re-renders drafts on demand. A local `node:http` entrypoint runs it via `pnpm --filter diaa preview:cms` (port 8080, serves `dist/` assets — build first). On the SPA side, `maybeEnableVisualEditing()` (fired after `installController()` in boot phase 2, no-op unless `window.__PREVIEW__`) lazy-loads `@sanity/visual-editing` — confirmed isolated to its own chunk, absent from production HTML — wiring click-to-edit overlays, a history bridge into `Ctrl.navigate()` (new generic `onNavigationCommitted()` observer hook fires after `pushState` so the Presentation URL bar tracks SPA navigation), and a refresh flow that re-fetches `/tmhgne.json` (`reloadPkgFromNetwork()` in `cache.ts`) and rehydrates the current route without a full reload. The stega filter excludes every routing/URL-bound result key (`slug`, `href`, `image`, `video`, `coverImage`, `coverVideo`, `url`) so route keys, filenames, and asset URLs stay byte-clean while titles and Portable Text stay editable-by-click. Deps: `@sanity/visual-editing ^5.7.3`, `@sanity/preview-url-secret ^4.1.2`.

Deploy with Vercel dashboard project `diaa-preview`, root directory `apps/preview`, **Deployment Protection off** (the Studio iframes it directly; access is gated by the preview-url-secret session cookie instead) — see `apps/preview/README.md` for the full env var + settings table.

- **Scroll input is locked for the full duration of every page entrance animation** (`apps/fe/src/app/page-manager.ts`). `PageManager.animateCurrentPageIn()` now calls `App.scroller.pause()` before awaiting the page's `in()` and `resume()`s it in a `finally` (so a throwing `in()` can never leave scrolling stuck). The pause only ignores user wheel/touch/keyboard/native-scroll input — the damping RAF and the programmatic scroll restore (which runs earlier in `initCurrentPage()`) are unaffected — and the page's `onScroll` subscription is still wired only after the resume, so per-page scroll hooks never fire mid-entrance. Applies to both first boot (phase 5) and every SPA navigation. Both scroller implementations (`NativeScroller`, `Scroller`) already expose `pause`/`resume`.

- **The detail / Contact / Imprint title nav now fades out when the outro reaches the vertical midpoint of the viewport, not its bottom** (`apps/fe/src/routes/detail/detail.ts`, `apps/fe/src/app/primitives/rich-text-page.ts`). The scroll trigger changed from "outro top edge crosses the bottom of the viewport" (`top <= clientHeight`) to "outro top edge crosses 50% of the viewport" (`top <= clientHeight * OUTRO_NAV_HIDE_RATIO`, ratio `0.5`). The old `OUTRO_ENTER_EPSILON` guard (which prevented a scroll-0 false-trigger on short pages whose content ended near the viewport bottom) is removed — a halfway threshold is inherently past that boundary, so it's no longer needed. Same change in both the detail page and the shared `RichTextPage` base (Contact + Imprint) so all three stay consistent.

- **Browser/tab title format is now "`<site name>` - `<page title>`" (hyphen) across detail, Contact, and Imprint pages** (`apps/fe/scripts/sanity-content.ts`, `apps/fe/scripts/routes-plugin.ts`). Detail pages previously emitted `<detail title> — <site name>` (em dash, site name last); the order is now reversed and the separator is a hyphen, e.g. `Diaa - Project Name`. Contact and Imprint, which previously used the bare page title with no site prefix, now follow the same `Diaa - Contact` / `Diaa - Imprint` shape. `sanity-content.ts` composes all three titles (falling back to the bare page title when `siteOptions.name` is unset). Because Contact and Imprint are **static** route folders — not star-prefixed CMS templates — the routes plugin's static loop previously derived their tab title from the shell `<title>` (a bare `{{siteTitle}}` → "Diaa") and ignored `page.title` entirely; it now prefers the composed Sanity title when it differs from the bare capitalised folder name, applying it to both the SPA cache title and the baked `<title>` (so a hard load / crawler sees it and there's no "Diaa" → "Diaa - Contact" flash). Home and About (whose Sanity title is still the plain folder name) are unchanged. On-page nav headings still read the bare `data.title`.

### Fixed

- **Scrolling is now truly locked for the entire page transition, not just the entrance animation** (`apps/fe/src/app/controller/index.ts`, `apps/fe/docs/controller.md`, `packages/kido/src/native-scroller.ts`, kido `0.1.4` → `0.1.5`). Two stacked holes let the user scroll mid-transition (visible when navigating home → detail). **(1) The pause was porous:** `NativeScroller.pause()` only skipped the smoothing logic — `onWheel`/`onTouchMove`/`onKeyDown` early-returned *without* `preventDefault()`, so the browser's default native scrolling passed straight through, and `handleNativeScroll` had no pause guard at all, so scrollbar drags and trailing trackpad momentum moved the page *and* were synced into scroller state. Paused input handlers now `preventDefault()` (ctrl-wheel zoom still allowed; only scroll keys swallowed), and the native `scroll` handler snaps the viewport back to the held position while paused (guarded to skip the no-op `setScroll` that would strand a stale `_preventNextNativeScrollEvent` flag). **(2) The pause window was too narrow:** it only spanned `page.in()` (via `PageManager.animateCurrentPageIn()`), leaving the out phase + curtain scrollable. `Ctrl.navigate()` now pauses the scroller the moment `App.mutating` is set and resumes it wherever the lock clears (`_in()`'s `finally`, the no-callbacks early return, and the safety-valve timeout — so a hung transition can't leave scrolling dead). The inner `animateCurrentPageIn` pause stays for first-boot entrances; pause/resume are idempotent so the nesting is harmless. Programmatic `scrollTo(pos, true)` (`updateAll` path) intentionally bypasses the pause, so back-nav scroll restore still works mid-lock. Kido rebuilt (`pnpm --filter kido build`).

- **Home→detail cover handoff no longer doubles the shadow on transparent covers** (`apps/fe/src/app/controller/transitions/home-to-detail.ts`, `apps/fe/src/routes/detail/detail.ts`). The shadow on the "Uselessly" cover is **baked into a transparent image asset** (no CSS shadow), so any two stacked visible copies composite their semi-transparent shadows into a **doubled/darker shadow**. The index→entry bridge left two such overlaps: **(A)** during the transition the original home reveal figure stayed visible (`HomePage.out()` keeps `.home__text-gpu` on screen) while the pixel-identical clone was stacked exactly over it, both coexisting until the home section is removed ~150ms in; and **(B)** in `DetailPage.in()` the real `.detail__cover` was held **solid** while the clone faded **down over it**. Both are now single-copy: (A) `out()` sets the original figure `visibility: hidden` the instant it clones it (instant, vs. the figure's 800ms opacity transition), so only the clone shows; (B) the cover is held **hidden** (`opacity: 0`) beneath the solid clone for the whole entrance, then clone and cover are **hard-swapped in a single frame** at the end — invisible because they are the same image at the same position, with no crossfade white-bleed. (B) is applied to both the active bridge path in `in()` and the dormant `mobileEntrance()` slide path (behind the `MOBILE_COVER_ENTRANCE_SLIDE` revert switch). Rationale comments in both files updated. Opaque covers are visually unchanged.

- **kido tab-visibility resume no longer corrupts in-flight animations** (`packages/kido/src/tab.ts`, `packages/kido/src/raf.ts`, kido `0.1.3` → `0.1.4`). On `visibilitychange → visible`, `Visibility` was handing subscribers `performance.now()` (an absolute timestamp) where the RAF hub expected the wall-clock **duration** the tab had been hidden. `RafHub._onResume` added that huge value to every live item's `startTime`, so any animation in flight when the tab was backgrounded/foregrounded (app-switch gesture, notification banner, lock/Face-ID prompt — all of which fire `visibilitychange`, especially on mobile) had its clock poisoned and snapped to its end or froze. This was the root cause of the intermittent "DIAA mark appears without fading in" glitch on return-to-home: a `visibilitychange` landing inside the 1200ms beat fade-in jumped it straight to opacity 1. `Visibility` now stamps `performance.now()` on hide and passes the elapsed hidden duration on resume (guarded to 0 on first-ever call and against negative skew); `RafHub._onResume` shifts only already-started items (`startTime !== 0`) so animations registered while hidden still initialize normally on their first visible frame. Both `onHidden`/`onVisible` are also now idempotent against duplicate same-state events. Requires no consumer changes — rebuild kido (`pnpm --filter kido build`, done).
